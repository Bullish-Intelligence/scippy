# Changelog

All notable changes to Scippy are in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- A union gets one occurrence for each candidate. When a reference is ambiguous and every candidate is a method, an attribute, or a property of a class of the project, the index now holds one occurrence for each candidate, all at the same range, in the order of the symbols. This is a true union: `e: ListExpr | TupleExpr` then `e.items`, or an `isinstance(x, (A, B))` guard. The set must have at most 4 candidates, and no owner class may be the same class as another owner or a subclass or superclass of it (the inheritance data of `inherit.rs`, with transitive bases). Override chains (`ChainedPlugin.report_config_data` and `Plugin.report_config_data`), module-level names, mixed kinds, members of external classes, and sets of more than 4 candidates keep the old result: no occurrence. **Several occurrences can share one range.** The SCIP specification (`scip.proto`, message `Occurrence`) allows it: it asks an indexer to bundle information of one symbol into one occurrence and says nothing against several symbols at one range. Occurrences of one document are not required to be unique by range. The trace marks such a reference as `union` instead of `ambiguous`. `references_ambiguous` still counts it, and the new `references_union` (a part of `references_ambiguous`) counts the unions. In `index --json` the field is `value.references.union`. The metalayer store is unchanged in kind: the reference row stays `ambiguous` with its candidates, and the `occurrence` table (its key holds the symbol) gets one row for each candidate. `metalayer explain --to SYMBOL` lists the site as `ambiguous` for each candidate. Union references on the six oracle corpora: mypy 194, pydantic-ai 110, celery 15, stdlib 10, scrapy 1, rich 0. Remaining ambiguous references that are no union: mypy 119, pydantic-ai 39, stdlib 78, celery 11, scrapy 4, rich 1. Strict (exact) recall and precision do not move. The oracle reports covered recall (see `scripts/oracle/RESULTS.md`).
- The oracle (`scripts/oracle/`) tells exact from covered. Exact: Scippy has one symbol at the position and it matches (the strict numbers, as before). Covered: Scippy's set holds the scip-python target. A position with several Scippy symbols is its own named number (`multi_symbol`, with `multi_covered`, `multi_not_covered`, and `multi_owner_class_coarse`), and it is never an exact match. New named numbers `covered_recall_pct` and `covered_precision_pct`. `gate.py` allows several symbols at one occurrence and prints their count against the baseline. It fails when a set is not a true union: a symbol that is no member of a class, more than 4 symbols, or owner classes that are one class or related by inheritance (`owners.py` reads the base classes from the sources of the corpus and from both indexes). `difftool.py` lists the multi-symbol occurrences of the candidate with the reason. Unit tests cover the metrics, the gate, and the owner relation.

### Changed

- The fork pin moves to `6c1b28c`. The fork stops the member route of a store from looping through the class (`056ae90`): `super().__new__` in a class with the base `dict` gives `dict.__new__` only. It hoists every local binding of a function (`5cf9449`, see the entry about the reconciler below). It decides the return annotations that name no class in the graph (`e27e46a`). The allowlist (`scripts/oracle/gate-allow.txt`) loses the two celery R4 lines and gains 9 stdlib H1 lines for `xml/dom/expatbuilder.py` (`self.document.doctype.entities` has no project target in scip-python).
- The fork pin moves to `32b5325`: `object` comes after all other base classes at every level, and a call of `super()` follows a generic base class. In `argparse.py`, `super(ArgumentParser, self).__init__` is `_ActionsContainer.__init__` again (the allowlist line is gone). 34 `super().__init__()` locations get the project target that scip-python gives (pydantic-ai 31, mypy 2, stdlib 1). Strict recall: pydantic-ai 96.0400 to 96.2331, stdlib 98.0304 to 98.0320, mypy 94.2590 to 94.2603. No new real wrong target. Two celery locations (`celery/canvas.py:1352:35`, `:1354:23`) changed from resolved to ambiguous. The pin `6c1b28c` resolves them again, so they are no longer in the allowlist. Every class reaches `object` from its self scope now, so `self.__dict__` and similar members resolve in more places.
- Accuracy on the six oracle corpora with the fork pin `e945e1d`, the kind A identity merge, and the function rule, against `df9cecaa` (see `scripts/oracle/RESULTS.md`). Ambiguous references: rich 18 to 1, stdlib 155 to 88, celery 58 to 24, mypy 339 to 313, pydantic-ai 175 to 149, scrapy 12 to 5. Real wrong: celery 17 to 2, stdlib 10 to 9, mypy 0 and rich 0 stay. Strict recall rises on every corpus. One known loss: `argparse.py:1887:48` (`super(ArgumentParser, self).__init__` with two bases) now names `object.__init__`, because the base class search of the fork is depth first and reaches the implicit `object` of the first base before the second base. The gate allowlist (`scripts/oracle/gate-allow.txt`) lists the other changed locations with a reason each.
- The reconciler has no function rule. The fork pin `6c1b28c` hoists every local binding of a function (`5cf9449`), so a name that a function binds is local to the whole function, and a path that bypasses the binding no longer reaches a binding outside the function. The rule of the reconciler (142 lines in `reconcile.rs`) is gone. The fork rules of `e945e1d` could not hoist the binding: the stitcher dropped the hoisted path as a similar path of the flow path. Each hoisted definition is a node of its own now, so the path stays.
- The fork pin moves to `e945e1d`. The fork now stores source info in a compact form (`a7ef937`), so `anchor_from_info` takes the source info by reference to the stored value. The fork also adds Python rules for names in a target of a tuple or list assignment, a dotted name in a string annotation, `nonlocal`, a local variable in a function body, and the store forms of the stores pattern (`1d4de04` to `ff50f41`).
- A variable or a field that rebinds a class or a function of its own container shares the symbol of that class or function. Before, `Future = _asyncio.Future` after `class Future`, and `self.plain = v` next to a property `plain`, were two entities, and a reference to the name had two targets and was ambiguous. A field takes the members of its class as siblings. The shared symbol keeps the kind of the class or of the function (`Class`, `Function`, or `Method`), and its facts (digests) come from the class or the function, also when the variable comes first in the file.
- The accuracy oracle (`scripts/oracle/`) reports named numbers: strict recall and precision, owner-class coarse, import-prefix convention, same-name other class, and real wrong. It reads a top-level module name of scip-python without backticks (`dataclasses/Field#`), and it has the classes `sp_first_binding` and `sp_builtin_type_attr`. On the standard library, wrong targets fall from 131 to 10 with no change of Scippy output. New: `track.py` (per-class CSV and deltas), `gate.py` and `run_gate.sh` (regression gate, not part of `pm verify`), `difftool.py`, `fetch_corpora.sh` (pinned corpora, now with scrapy 2.6.3 and celery 5.3.6), and `README.md`.
- The lookup of the build threads runs at most `AHEAD` files ahead of the merge, where `AHEAD` is 4 times the build threads and at least 16. Before, the lookup queued every file at once, and up to 177 of the 187 graphs of mypy waited for the merge together, 23 to 26 MiB each. The file that the merge needs is always in the window, so the merge never waits for a file that the lookup did not reach. The `.scip` and `--trace` files do not change. Peak memory on mypy, graph cache off, one run each: 3.91 GiB with 1 build thread, 4.36 GiB with 2, 4.70 GiB with 4, and 5.47 GiB with 8 (7.67 GiB before). On rich it is 1.03 GiB and on stdlib 2.81 GiB with 8 threads (1.25 and 3.35 GiB before). A test builds 100 files behind a slow first file at 2 and 8 threads and with a cold and a warm graph cache.
- The memory estimate of a shard for the scheduler rises with the build threads up to 1.5 times for its growing part (it was 2 times), because the window lowered the measured ratios to 1.12, 1.20, and 1.40 for 2, 4, and 8 threads.
- The Python rules set no scope depth cap (`max_scope_depth: None`). The cap of 1 changed no position in the `.scip` file of rich, stdlib, and mypy, and saved no time. The `--trace` file of rich and mypy is the same. On stdlib it differs in 242 of 88,832 lines: the counts `ends` and `shadowed` of 234 resolved references and 6 bounded references (the targets are the same), and 2 references that were `not-targetable` with the cap are `bounded` without it.
- `BindingRules::max_scope_depth` is gone. The fork engine no longer has the scope depth cap (`StitcherConfig::with_max_scope_depth`), and no pack set it. A pack that built `BindingRules` with this field must drop it.
- `resolve` starts as many threads as it can and continues with fewer when a thread cannot start, as the build already did. When no thread starts, the calling thread resolves the references. Before, a thread that could not start stopped the run with a panic.
- The fork pin moves to `4e20bf8`, with three speed changes that keep the output. The join test of the stitcher reads the leading symbols of each database path from a table (`804ae65`). `can_be_shadowed` walks the edges in place, with no copy (`95dbbe2`). The vendored `tree-sitter-graph` formats each statement text once per stanza and remembers the value of an inherited scoped variable for each node (`8c068ea`). The `replace` function borrows its cached regex (`c5b3a6e`). On mypy at one build thread and one resolve thread, one run each, the user-space instructions fall from 995.8 to 840.9 billion (-15.6 percent). At default threads they fall from 1032.2 to 843.1 billion (-18.3 percent). Wall time and user time were not compared: the machine was under load. The search cost `arena_cells_max` in `--json` falls by 489 cells in the golden files (1168 to 679, and 2156 to 1667), because the join test no longer reverses the precondition of each candidate in the search arena; the golden files hold the new values. The `.scip` and `--trace` files of rich (at `09371f7`) and mypy (at `8c068ea`, the same change set without the `replace` borrow) are equal to the files of the previous pin, except for the version string.

### Fixed

- The two tests of `check --project-root` and `check --root` no longer share the directory `check-root`. Run as threads of one process (`cargo test`), they moved the same directory and failed in 6 of 6 runs. Nextest runs each test in its own process, so the gate did not show it.
- The peak memory of the build threads in this file and in `README.md` and `scripts/oracle/RESULTS.md` is in GiB, not GB. The text about `arena_cells_max` says "a few cells": one cell in the fixtures, 286 cells on rich.

## [0.2.0] - 2026-11-22

### Added

- `scippy notes` resolves trusted, source-bound note facts in a persistent JSON-lines worker.
- Incremental note updates trace successful lookups and lookup misses. Atomic batches invalidate affected references.

- `scippy index --build-threads N` builds the graphs of the files of one shard on `N` threads. The default is the rule of `--resolve-threads`: `--jobs` divided by the number of shards that run at once, at least 1. A file builds without any other file, so workers parse the files and build the graphs of the files that the graph cache lacks, each in a stack graph of its own. The main thread looks the files up in the cache, adds each graph to the engine in file order, and stores each new graph in the cache in file order. The compiled TSG rules are shared by all workers (`Arc` and `OnceLock`: `StackGraphLanguage` is `Send` and `Sync`), so a rule set compiles once. A file that fails to build gives the same `bind-error` diagnostic at every thread count, and a panic in a worker ends the run with that panic. The `.scip` and `--trace` files are byte-identical at 1 and 8 threads, with the graph cache off, cold, and warm, and equal to the files of the previous release on rich, stdlib, and mypy. Wall time on 8 cores (shared machine, graph cache off): rich 10.9 s to 5.1 s, stdlib 57.4 s to 37.6 s, mypy 94.3 s to 43.1 s. The peak memory rises: rich 0.55 to 1.25 GiB, stdlib 2.20 to 3.35 GiB, mypy 4.01 to 7.67 GiB. The estimate of a shard for the scheduler rises with the build threads, up to 2 times for its growing part. `--build-threads 1` keeps the previous memory and takes 5% to 8% longer than the previous release (one run each).
- `scippy index --resolve-threads N` resolves the references of one shard on `N` threads. The default is `--jobs` divided by the number of shards that run at once, at least 1, so the shard threads times the resolve threads do not exceed `--jobs`. The fork pin moves to `dc75eb5`, which adds `PartialPaths::freeze` and per-thread overlays of the frozen arenas. Each thread takes chunks of 16 references and writes each result to the slot of its reference, so the `.scip` and `--trace` files are byte-identical at 1 and 8 threads and equal to the files of the previous pin. Wall time at `--jobs 8`, one shard, graph cache off: rich 13.1 s to 10.7 s, stdlib 112.1 s to 59.7 s, mypy 189.9 s to 95.9 s. Peak memory: mypy 4.20 GB to 4.16 GB, stdlib 1.59 GB to 2.33 GB. A test checks that 1, 2, 4, and 7 threads give equal bindings.
- `scippy index --json` reports the cost of the searches in `value.references.search_work`: `searches`, `work_total`, `work_max`, `queue_length_max`, and `arena_cells_max`. The stitcher already counted this work and Scippy dropped it. The values hold no time. They are the same for each run and each `--jobs`. The change is additive: `format_version` stays 1, and the JSON Schema needs no change because it allows additional properties. The golden files of `index` hold the new block.
- The Python pack repairs three constructs of Python 3.14 that `tree-sitter-python` 0.23.5 rejects, and gives the warning `repaired-syntax` instead of `syntax-error`: PEP 758 `except A, B, C:` and `except* A, B:` (the commas become `|`), PEP 750 `t"..."` (the prefix becomes `f`), and PEP 696 type parameter defaults (the default is blanked, so the names inside it get no occurrence). On `semantic-views`, 17 files that Scippy skipped now index.
- A test in `opt:slow` guards the search of an annotated factory chain. The fixture `annotated_chain` has a chain of six factories with `-> Address` and 20 member chains. It asserts 0 bounded references and the target of each use. With the fork pin `cda555a` it fails with 20 bounded references. It also bounds the search work (total 135,000 and largest search 2,800; measured 106,270 and 2,259). With `cda555a` the total is 18,091,672, so the bound fails on its own.

### Changed

- The engine builds the graph of each file in a stack graph of its own and then loads it, as it loads a graph from the cache, also with one build thread. Before, a build wrote into the stack graph of the engine, and only a cache hit loaded a stored graph. Now a cold cache, a warm cache, and every number of build threads give the same engine. The `.scip` and `--trace` files do not change. The search cost `arena_cells_max` rises by a few cells: by one cell in the fixtures (2155 to 2156 in the golden files `index-incomplete.json` and `index-published.json`), and from 280,131 to 280,417 on rich. The cause is that the arena of the engine holds the cells of the stored paths and no cells of the build.
- The fork pin moves to `c8e54f0`, with two fork changes that speed up an index and keep its output. The shadow check of the stitcher decides both directions in one pass and `can_be_shadowed` allocates less (`349fb5d`). The `replace` function of the vendored `tree-sitter-graph` keeps each compiled regular expression in a cache of the thread (`c8e54f0`). Before, the Python rules compiled the pattern on each call: 7608 compiles with 21 distinct patterns on ASTitch. On ASTitch (59 files, cold) the user-space instructions fall from 152.06 to 133.86 billion (-12.0 percent) and the user CPU time from about 21.0 s to 17.9 s. On agentman (62 files) the instructions fall from 101.77 to 87.69 billion (-13.8 percent). The `index.scip` files have the same SHA-256 as before and the `references` block of `--json`, `search_work` included, is equal.
- The fork pin moves to `27e2435`, with three fork changes: a vendored `tree-sitter-graph` whose syntax node id has the width of `usize` (this fixes a flaky "Duplicate variable" failure under load), `collections.abc` stubs with `isinstance` narrowing through a name that holds a tuple of classes, and a class member fan-out that only includes a method that can store an attribute of its first parameter. The Python pack sets the new stitcher option `max_scope_depth` to 1 in the resolve step (new field `BindingRules::max_scope_depth`; the TypeScript pack sets none). Against the pin `930f3e2`, in one paired run at 8 jobs: rich raw recall 96.80% to 96.82%, mypy 94.24% unchanged, stdlib 97.72% to 97.73%. Precision is unchanged on rich and stdlib, and falls from 95.60% to 95.56% on mypy. Wrong targets are unchanged (0, 0, 131). Bounded references on the standard library fall from 26 to 8 (the depth cap alone ends 2 of the 10 that remain without it as not targetable, and it changes no output). The wall time falls from 290 s to 168 s on mypy and from 170 s to 120 s on the standard library. On mypy, 2 locations go from resolved to unresolved (`semanal_newtype.py:139`, `semanal_typeddict.py:492`); scip-python agrees with neither answer.
- The fork pin moves to `930f3e2`. The fork narrows more `isinstance` guards, follows the return annotation of a string that holds one plain name, and keeps one more similar path at an attribute store. This restores most members that the pin `3240d66` lost. On mypy, the raw recall rises from 94.19% to 94.24%, and 21 of the 27 locations that `3240d66` lost resolve again. On rich, the raw recall rises from 96.78% to 96.80%, and the bounded references fall from 4 to 0. There are no wrong targets. On mypy, 3 locations go from resolved to ambiguous.
- The message of the `repaired-syntax` diagnostic says that a name in blanked text gets no occurrence.

- The fork pin moves to `3240d66`. The fork contracts the graph of each file, and a call of an annotated function follows the return annotation only. On mypy, the bounded references fall from 330 to 0, the raw recall rises from 94.11% to 94.19%, the wall time falls from 1,515 s to 533 s, and the peak memory falls from 5.45 GB to 4.22 GB. There are no wrong targets.
- `metalayer show` no longer prints `parent`; facts schema 10.
- `scippy metalayer check` takes `--project-root`. The old `--root` stays as a hidden alias.
- Metalayer facts schema version 9: the unused `root_id` column is gone. Older facts databases rebuild on open.

### Fixed

- A lambda parameter is a local symbol of its own, not the parameter symbol of the enclosing function (item 32).

## [0.1.0] - 2026-11-16

### Added

- `scippy index` writes a SCIP index of a project, with deterministic output and atomic writes.
- Python pack: definitions, imports, references, builtins and stubs as external symbols, and override relationships.
- Python resolution with the Stack Graphs fork: cross-file names, packages, aliases, `isinstance` narrowing, class keyword arguments, container element types, and `Optional[...]` annotations.
- Loci Markdown pack: notes, headings, blocks, links, and embeds, with the same states as `loci-core`.
- Loci roots, `roots_file`, and the ignore list: one index over notes and code repositories.
- TypeScript pack as a calibration guard (ADR-011). It is not supported.
- Parallel shards with `--jobs` and `--memory-budget`.
- Graph cache of file graphs, on by default.
- Experimental metalayer (SQLite): facts of each run, with a status for each file.
- `scippy metalayer` commands: `show`, `files`, `relations`, `edges`, `explain`, and `check`, with a versioned JSON envelope.
- Experimental identity store: entity IDs rebound across runs (tiers T1 to T5 for code, M2 to M5 for notes).
- `scippy metalayer entity` and `annotate` commands: `add`, `list`, `rm`, `status`, `accept`, and `reject`.
- `scippy index --json` and `--strict`.
- `scippy index` exit codes: 0 complete, 3 finished but incomplete, 1 failure, 2 usage.
- Accuracy oracle against `scip-python` (`scripts/oracle`).
- Testee gate and the `opt:slow` task for slow tests.
- Gate 6 conformance tests: core language names, invalid rules, a mixed run, creation order, and Loci CRLF notes.
- Oracle rerun for v0.1: Python on mypy and rich, Loci on the real vault.

### Changed

- The graph cache is on by default in the CLI.
- The default memory budget is a flat 50 GiB.
- The builtins and stubs graphs are built at build time and loaded in each run.
- The pipeline and the metalayer publish code are split into named modules and phases.
- `scippy index` is one entry point with an `IndexMode` value.
- The tests run with the `gate` profile.
- Identity tier T3 needs an equal body digest for a top-level class. Two classes with the same name no longer bind as moved.
- `scippy --version` prints `scippy 0.1.0`.

### Known limits

- The metalayer and the identity store are experimental. Entity IDs and the schema can change.
- Lambda parameters share the parameter symbol of their enclosing function (fork item 32).
- A whole-string annotation such as `"Optional[Foo]"` is not followed.
- The identity evaluation measured Python at scale only. Other languages have few cases.
- The tests cover Linux x86_64 only.
- The Loci comparison with `loci-core` was not rerun after the note, heading, and block change.
